# PersonalTrainerOPS — Style Guide Resolver

Status: ACTIVE RESOLVER
Version: 1.0
Date: 2026-09-01
Authority: current accepted implementation + current product/brand decisions + HenricoOPS visual governance

## Purpose
Make the current PersonalTrainerOPS expression portable without inventing a new visual identity during Base Pack migration.

## Brand/naming
- Semantic project name: `PersonalTrainerOPS`.
- Physical repo/path may remain `personalops` until a separate migration.
- Historical `PersonalOps` strings are provenance and should not be propagated into new public/product naming.

## Expression principles
- operational, modern and clear for frequent professional/student use;
- training context must be immediately legible;
- visual hierarchy should reduce friction in student management, training creation and training execution;
- professor/admin/student roles must remain distinguishable by information and permissions, not decorative themes alone;
- exercise/media is functional content, not decorative filler.

## Current visual source
Exact current colors, typography, component styling and media treatment are resolved from the accepted current implementation and any newer explicit visual decisions. This resolver does not fabricate token values.

## Photography / exercise media
Use licensed/approved exercise imagery or current product assets according to rights and product contracts. Do not create misleading anatomical/training guidance or represent generative visuals as authoritative instruction without review.

## Motion
Motion/timers/feedback may support training execution but cannot interfere with readability, reduced-motion needs or core task completion.

## Voice relationship
Copy is practical, specific to personal training and role-aware. Avoid generic wellness/productivity language and any drift toward life-management positioning.

## Forbidden drift
- `PersonalOps` as new semantic product naming;
- generic productivity/habits/energy language;
- provider-default fitness neon/gym aesthetic without authority;
- visual hierarchy that blurs admin/professor/student responsibilities;
- invented training evidence/metrics;
- inaccessible exercise execution interfaces.

## Validation
Use `DESIGN.md`, `DESIGN_SYSTEM.md`, `A11Y.md`, current role/journey contracts and applicable HenricoOPS visual gates.
